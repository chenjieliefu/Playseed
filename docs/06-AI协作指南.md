# AI 协作指南

## 开始任务

1. 先读 `AGENTS.md` 和 `docs/README.md`。
2. 根据任务读取对应文档，不把 `research/` 或旧版本验证记录当成当前需求。
3. 查看真实代码和测试，确认文档描述没有落后。
4. 先写清本次要改变的用户行为和完成标准，再修改实现。

## 权威来源顺序

出现矛盾时按以下顺序判断：

1. 用户在当前对话中的最新决定。
2. 可运行代码和自动测试表现出的事实。
3. `docs/` 中的当前文档和 `AGENTS.md`。
4. 根目录 README 的摘要。
5. `research/`、历史验证记录和品牌过程稿。

如果代码和当前文档不一致，先查明真实行为，再在同一任务中修正文档。

## 修改范围

- 产品流程变化：更新 `02-用户创作流程.md`。
- GPT、Godot、Python、文件或安全结构变化：更新 `03-系统架构.md` 和 `07-决策记录.md`。
- 功能完成或边界变化：更新 `04-当前能力与边界.md`。
- 优先级或阶段完成标准变化：更新 `05-路线图.md`。
- 新的长期产品原则：更新 `01-产品定义.md`。

不要把运行日志、临时截图、生成工程或测试夹具写成产品计划。

## 实现完成标准

一项功能只有同时满足以下条件才算完成：

- 用户能从现有主流程找到并完成操作。
- 界面状态与后台真实状态一致。
- 数据保存、失败、取消和旧版本保护得到处理。
- 有与风险相称的自动测试或可复现人工验证。
- 当前能力文档已经更新。

视觉按钮存在、GPT 说“已完成”或单次演示成功，都不能单独作为完成依据。

## 交接格式

其他 AI 完成一轮工作后，使用下面的格式留下交接：

```text
目标：本轮解决的用户问题
完成：已经落地的行为和文件
验证：运行的命令、结果和人工检查
边界：仍然不能做或没有验证的内容
下一步：下一位 AI 应从哪个文件、问题或失败样本继续
```

## 开发检查

后台或数据变更至少运行：

```sh
python3 -m unittest discover -s tests -v
```

界面、输入或游戏运行变更按需运行：

```sh
"./Playseed.app/Contents/MacOS/PlayseedRuntime" --headless --path app --script creator_tests.gd
"./Playseed.app/Contents/MacOS/PlayseedRuntime" --headless --path app --script input_tests.gd
"./Playseed.app/Contents/MacOS/PlayseedRuntime" --headless --path app --script game_tests.gd
```

真实模型生成会消耗用户账户额度。优先用固定测试覆盖代码路径；只有生成质量或完整链路需要验证时才调用真实模型，并在记录里明确说明。
