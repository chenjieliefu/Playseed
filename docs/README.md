# Playseed 文档中心

这里是 Playseed 当前产品、技术和协作信息的唯一入口。文档描述 0.8.37 本机原型；代码和测试发生变化时，应在同一任务中更新相应文档。

## 阅读顺序

所有参与者先读：

1. [产品定义](01-产品定义.md)：我们做什么、为谁做、如何判断方向有没有偏。
2. [用户创作流程](02-用户创作流程.md)：用户从一句想法到游戏版本的完整路径。
3. [系统架构](03-系统架构.md)：GPT、Godot、Python 和本地文件分别负责什么。
4. [当前能力与边界](04-当前能力与边界.md)：已经做到什么、部分做到什么、尚未做到什么。

按任务读取：

- 素材制作、修复和验收：读 [素材质量标准](08-素材质量标准.md)。
- 当前执行阶段、连续开发留痕与停止交接：读 [开发执行记录](09-开发执行记录.md)。
- 切图、动画配置与版本验证：读 [帧动画使用与验收](10-帧动画使用与验收.md)。
- 产品规划和排期：读 [路线图](05-路线图.md)。
- 新手试玩和体验验收：读 [新手试玩与体验验收](11-新手试玩与体验验收.md)。
- 代码修改或多 AI 交接：读 [AI 协作指南](06-AI协作指南.md)。
- 对关键技术选择有疑问：读 [决策记录](07-决策记录.md)。

## 文档层级

| 位置 | 用途 | 是否代表当前方案 |
|---|---|---|
| `docs/` | 当前产品、架构、能力和路线 | 是 |
| `README.md` | 人类快速打开、使用和开发入口 | 是，但只保留摘要 |
| `AGENTS.md` | AI 进入项目时的最短规则与文档指针 | 是 |
| `research/` | 竞品实测、截图、证据和当时的落地记录 | 否，只作为研究依据 |
| `验证记录-*.md` | 特定历史版本的验证快照 | 否，只证明当时验证过的范围 |
| `assets/brand/*.md` | 吉祥物与图标的历史设计记录 | 否，当前选择以 `当前选定形象.md` 为准 |

## 维护规则

- 一个事实只保留一个权威位置，其他文件链接到它。
- “已实现”必须有代码和验证支撑；计划中的能力写进路线图。
- 当前能力变化时更新 `04-当前能力与边界.md`；流程变化时更新 `02-用户创作流程.md`；组件关系变化时更新 `03-系统架构.md`。
- 竞品研究和版本过程可以继续追加，但不得覆盖当前产品定义。
- 每次交接必须写出剩余问题，避免下一位 AI 把计划误认为完成。
