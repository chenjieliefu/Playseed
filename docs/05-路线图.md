# Playseed 路线图

路线按能力风险排序，不按示例游戏数量排序。每个阶段完成后再扩大范围。

## P0：提高小型 2D 游戏的成功率

目标：让不同类型的明确方案都能较稳定地产生第一版，并能连续修改三轮。

交付：

- 建立平台跳跃、俯视射击、经营、解谜、塔防或轻度 RPG 的固定验收样本。
- 将每个样本拆成操作、核心循环、胜负、重开和三轮修改检查。
- 改进生成规则和自动修复，使失败原因对用户清楚可见。
- 记录首次制作成功率、修改成功率和旧功能回归率。

完成标准：至少五种玩法各有一个独立规则的可玩样本；每种连续修改三轮时，原有核心需求不丢失；失败不会覆盖上一版。

当前进度：0.8.6 已加入自动操作探针，修通 macOS 原生文件选择，并整理首页输入区。平台跳跃、俯视射击、经营、解谜和塔防的五类固定方案及每类三轮修改任务已经写入统一验收矩阵；验收脚本会把结果隔离保存，避免污染用户项目。2026-09-06 五类第一版真实生成最终 5/5 通过，其中平台跳跃经过一次自动修复，其余四类一次通过。五类三轮修改现已完成，15/15 通过运行检查、旧操作探针和样本专项玩法检查，未触发自动修复，旧版文件保持不变。具体检查范围见当前能力文档；随后完成五款自动输入通关、四款失败路径与重开检查，并核对结算画面。射击结束状态报错和两款文字交叠已修正。普通用户体验和更大样本的稳定性仍未完成。

## P1：完成视觉素材链路

目标：用户提供或生成的角色、场景和界面素材真正进入游戏，画面风格保持一致。

交付：

- 接入图片视觉理解，让模型知道上传图片画的是什么、适合做什么。
- 接入角色和场景图片生成，并保存生成提示、尺寸、用途和来源。
- 支持角色切图、基础动画帧、背景分层和常用界面组件。
- 让右侧素材、动画、特效工具可以配置后通过对话加入游戏。
- 增加画面越界、文字遮挡、缺图和素材未使用检查。

完成标准：从用户参考图或平台生成素材出发，完成一个视觉风格统一的 2D 游戏；素材可以替换并形成新版本。

## P2：增加玩法深度和声音

目标：从一次性小循环扩展到有递进、有反馈的短游戏。

交付：

- 多关卡或波次、敌人行为、技能、升级、资源取舍和难度曲线。
- 音效、背景音乐和音量控制；记录素材授权和来源。
- 将玩法、画面、声音和操作反馈分项验收。

完成标准：一个新用户可以连续玩 10 至 15 分钟，理解目标，感受到难度递进，并能指出每轮修改带来的变化。

## P3：验证小规模 3D

目标：接通第一个真正的 3D 垂直样本，不把 3D 需求转成 2D。

交付：

- 从低多边形小房间或小岛开始。
- 接入模型、材质、第三人称或第一人称相机、碰撞、交互和基础动画。
- 增加穿模、相机、碰撞、光照和性能检查。
- 为 3D 生成定义新的工程结构，避免沿用单一 `game.gd` 的限制。

完成标准：用户能通过对话制作一个可走动、可互动、有明确目标和完成状态的小型 3D 游戏，并在目标 Mac 上稳定运行。

## P4：分享和发布

目标：创作者能把游戏交给别人直接玩。

交付：

- 先支持一个明确平台，建议从网页或 macOS 独立包中选择一个。
- 自动检查导出模板、启动、资源完整性和基础设备尺寸。
- 生成分享文件或链接，并保留对应源版本。

完成标准：未安装 Playseed 的测试用户可以打开游戏并完成一轮。

## P5：云端和多人产品化

目标：从单机原型变成多用户服务。

交付：账户、云端项目、对象存储、任务队列、执行隔离、额度和费用控制、监控、恢复、团队协作与发布治理。

完成标准：不同用户的数据和运行环境相互隔离，任务可恢复，费用可统计，核心创作流程不依赖开发者电脑。

## 当前下一步

用户最新优先级：先让平台稳定完成小型2D或3D游戏的制作、试玩、修改、恢复与源工程导出，再集中打磨美术和玩法。P2三段真人反馈已收集，但趣味性与单版10～15分钟体验未通过，暂不扩充样本内容；P4发布与云端也暂缓。3D仍明确限定房间寻物和基础静态模型，不承诺任意3D类型。

0.8.35补齐3D可玩区域自动取景检查。0.8.36保存制作方式，0.8.37补失败重试与过期请求保护。下一步以用户自己的新想法验证从确认到试玩、修改、恢复和导出的流程，优先修复妨碍“做出来、玩起来、改下去”的问题；不优先追加美术细节或长流程关卡。

### 基础素材阶段历史进展

P0 固定样本验证已完成。P1 已接通参考图片理解，以及单张图片生成、预览、采用入库和来源记录。当前通过“生成图片：描述”及聊天引导按钮开始，每次一张；不会自动生成整套方案素材。实现位于 `image_assets.py`，输入与游戏应用仍走 `resources.py`、`creator.py`、`producer.py`。

0.8.16已将方案现有素材条目接入对话引导，支持逐项选择、带画风预填生成请求和原生上传。0.8.17已支持用户为方案条目手动关联已入库图片，记录方案版本和用途，后续模型请求携带关联。0.8.18已将任务上传和生成后采用直接接入任务关联。0.8.19已接通复合条目拆分建议、用户确认和子任务准备，真实验证了角色与背景分项。一套新生成角色与背景已完成采用、关联和真实入场验证，边界遮挡通过正常修改流程修正，结果见当前能力文档。0.8.20已接通可选择的画风参考和来源记录。真实蘑菇样本出现不透明棋盘格底，未采用；0.8.21已完成透明像素检查、可审阅修复入口与不透明修复结果拒绝采用。0.8.22另接macOS本机主体分离，真实蘑菇已获得透明稿并在隔离样本采用，支持收边和深浅底预览；仍存在局部浅色残留。0.8.23继续打磨素材细节，补上显式浅色残边清理、透明原稿保护及前后对照，验收见[素材质量标准](08-素材质量标准.md)。0.8.24已补合成白色主体、细线和独立小主体的误删保护验证。真实白色长毛样本未通过，已隔离并保留限制。0.8.25已完成规则切图、帧动画预览与真实游戏修改/恢复验收，0.8.26已补可选底部对齐并经真实第6版验证；后续补充了界面图片、源工程导出和恢复专项；帧间轮廓和画风一致性作为进阶项保留。不要扩大3D范围，不要把单张成功当作完整美术生产线完成。
