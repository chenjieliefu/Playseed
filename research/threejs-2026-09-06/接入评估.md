## 与 Playseed 的关系

Playseed 当前界面和生成游戏均基于 Godot，素材生成只接通二维图片。Three.js 的 JavaScript 渲染器不能直接当作 GDScript 模块塞入现有桌面游戏。若做浏览器预览，需要新增浏览器界面或独立预览窗口及通信、输入、文件和安全边界。

建议优先考虑以下可分阶段验证的路径，而不是立即更换现有引擎：

1. 在开发工具侧，用 Three.js 制作尺寸明确的简单道具、场景布局或模型检查器。
2. 通过 GLB/glTF 交换几何、基础材质及支持的动画数据。
3. 用 Godot 承担实际游戏运行、碰撞、输入及最终画面验收。
4. 只有浏览器内模型预览成为真实用户需求时，再评估把 Three.js 加入产品前端。

[Three.js GLTFExporter](https://threejs.org/docs/pages/GLTFExporter.html)支持导出 GLB/glTF；[Godot 支持的三维格式](https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/importing_3d_scenes/available_formats.html)介绍其导入流程。该交换格式不能自动传递 Three.js 的游戏脚本、自定义着色器、浏览器后期或所有渲染效果，也不保证两端看起来完全一样。

Godot 本身已有三维渲染与材质能力。未来进入 3D 阶段，优先补齐真正缺少的模型来源、参考尺寸、多视图检查、碰撞、骨骼和动画链路。复杂角色的精细建模仍需专业建模工具或专门的三维生成服务配合；仅增加一个渲染库不是解决办法。

## 本次真实验证

验证文件位于 `.playseed/qa/threejs-bridge/`：

- Node 成功加载本地 Three.js 与 GLTFExporter。
- 创建尺寸 2×3×4、位置 (1,0,0) 的长方体，指定 roughness=0.65、metalness=0.1。
- 实际导出 2,060 字节 GLB；Node 端仅补充导出器所需的 FileReader Blob 读取兼容接口。
- Playseed 内置 Godot 4.7.2 通过 GLTFDocument 读取，得到一个 MeshInstance3D。
- 尺寸、位置、粗糙度和金属度均在浮点容差内一致，检查通过。

本次没有进行 GPU 画面优劣对比、复杂角色建模、骨骼动画导入、多材质贴图压力测试，也没有向正式产品添加 3D 入口。不能据此宣称“3D 建模更准更好看”已被证明。

## 下一步建议

保留已安装的 Codex 工具。在产品既定 3D 验证阶段，选一个简单、尺寸明确的道具和一个有纹理的模型，做 Three.js → GLB → Godot 的视觉与比例对照，再决定是否值得把该工具链产品化。当前素材清单任务可以继续推进，无需先重写 Playseed。
